# Orbit

Native macOS life organizer (SwiftUI + SwiftData), built with SwiftPM: `scripts/build-app.sh` produces a signed `build/Orbit.app`.

## Shipping changes

The owner installs updates through the in-app updater, which reads GitHub Releases on `AhmedWalid4499/Orbit`. After any change they should get:

1. Bump the version (semver) and publish: `scripts/release.sh <version> "<short user-facing notes>"`.
   This commits, tags `v<version>`, pushes, builds, and uploads `Orbit-<version>.zip` as a release asset.
2. Never publish a build that isn't signed with the Apple Development certificate: the updater refuses builds from a different team, and an unsigned build would reset Keychain and privacy permissions.

## Windows app

`windows/` is the Windows version (Electron + React + TypeScript). It reads and writes the same Supabase `orbit_records` rows as the Mac app's `CloudSync.swift`, so field names in `windows/src/renderer/src/lib/models.ts` must match the Mac encoders, and dates must be ISO strings without milliseconds. `scripts/release.sh` also builds the Windows installer (`scripts/build-windows.sh`, needs Rosetta on Apple silicon) and uploads `Orbit-Setup.exe`, its blockmap and `latest.yml` (read by the Windows updater) to the same release. `ORBIT_SKIP_WINDOWS=1 scripts/release.sh …` publishes a Mac-only update and carries the previous Windows files over unchanged. Preview the window with sample data: build with `npx electron-vite build` in `windows/`, run `node windows/scripts-preview.cjs`, open `/?demo`.

## iPhone app

`iOS/` is Orbit for iPhone. It compiles the Mac app's `Sources/Orbit/{Models,Design,Services,Views}` directly, so data, sync, the assistant and most sheets are shared; only the phone screens in `iOS/OrbitPhone` are its own. That means shared code must build for iOS too:
- Use `Platform` (`Design/Platform.swift`) instead of AppKit: `Platform.open`, `.copy`, `.userName`, `PlatformImage`, `OpenSettingsLink`, `.sheetFrame(width:)` (Mac-only sheet sizes), `.orbitLink`, `.orbitCheckbox`, `.onEscape`, `AdaptiveStack`, `PageHeader`, `Theme.pagePadding`. Put anything Mac-only under `#if os(macOS)`.
- Mac-only files are listed in `scripts/gen-ios-project.py` (`MAC_ONLY_SERVICES`, `MAC_ONLY_VIEWS`). `iOS/Orbit.xcodeproj` is generated by that script; edit the script, not the project.
- Check both builds after shared changes: `swift build` and `scripts/run-ios-sim.sh -demo` (launch options: `-open <tab>`, `-sheet plan|review|card|assistant|settings|capture|search`).
- `iOS/Support/Shortcuts/*.shortcut` (bundled; Money › Auto-log card payments shares them) are built and signed by `python3 scripts/make-shortcuts.py`; rerun it if `LogBankMessageIntent`/`LogCardPaymentIntent` parameters change.
- Apple Watch: `iOS/OrbitWatch` (app) and `iOS/OrbitWatchWidgets` (complications), embedded in the iPhone app. The watch shows a `WatchSnapshot` the iPhone sends over WatchConnectivity (`iOS/OrbitPhone/WatchBridge.swift`) and asks the iPhone to act (`WatchAction`); both types live in `iOS/Shared/WatchPayload.swift`. `gen-ios-project.py --no-watch` leaves the watch out.
- The owner has a free Apple account: `scripts/install-iphone.sh` installs on the connected iPhone and must be re-run every 7 days. There's no TestFlight or in-app updater on iPhone. If Apple refuses the App Group, the script installs without widgets.

## Android app

`android/` is Joshu for Android: a Vite + Capacitor app that reuses the Windows renderer (`windows/src/renderer/src`, imported as `@/`) with its own phone shell, bridge and screens in `android/src` (`~/`). `android/src/bridge.ts` implements the same `window.orbit` API as the Windows preload (Claude, Google sign-in, key vault, updates), so shared screens run unchanged; Android-only pieces (Keystore-encrypted secrets, Google loopback sign-in, reading bank SMS, speech) are in `android/native/app/src/main/java/com/personal/orbit/OrbitNativePlugin.java`. A Vite plugin shows "Orbit" as "Joshu" in the shared screens at build time; don't rename anything internal. Phone layout overrides for desktop screens live in `android/src/mobile.css`.
- Build: `scripts/build-android.sh` → `build/Orbit.apk` (version from `VERSION`). It uses `~/.local/android-tools` (JDK 21 + Android SDK) and signs with the release key in `~/Library/Application Support/Orbit/android/` (password in the Keychain, "Orbit Android keystore"). Every update must be signed with that same key.
- Preview: `npm --prefix android run dev`, open `http://localhost:5199/?demo` at phone width.
- The app looks for `Orbit.apk` on the latest GitHub release to offer updates.

## Widgets

Desktop widgets are a WidgetKit extension in `Widgets/` (SwiftPM can't build extensions). `scripts/build-widgets.sh` compiles it with `swiftc` and signs it, sandboxed, with the `Y2K55S3UA9.com.personal.orbit` app group. `build-app.sh` calls it and assembles and signs the whole app in a temp folder, because the iCloud-synced Desktop adds file attributes that codesign rejects. The app writes `widget.json` to the group container (`WidgetBridge.swift`); keep its types in step with `Widgets/OrbitWidgets.swift`.

## Notes

- Secrets live in one Keychain item (`Keychain` in `Services/Claude.swift`); never put keys in files.
- Siri and Shortcuts: `Services/OrbitIntents.swift`. `scripts/build-app.sh` runs `appintentsmetadataprocessor` on SwiftPM's `.swiftconstvalues` to produce `Metadata.appintents`; without it the intents don't show up in Siri or Shortcuts.
- Public card page: `docs/card/index.html`, served by GitHub Pages (main, /docs) and reading the Supabase `public_cards` table (`supabase/public_cards.sql`).
- `ORBIT_SNAPSHOT_DIR=... ORBIT_SNAPSHOT_DEMO=1 build/Orbit.app/Contents/MacOS/Orbit` renders every tab to PNG with in-memory demo data and makes no network calls.
